# adopt-upstream-long-term-memory - Work Plan

## TL;DR (For humans)
<!-- Fill this LAST, after the detailed plan below is written, so it summarizes the REAL plan. -->
<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**Who this is for and what changes for them:** Luke, talking to a character on the desktop or in the browser. Today the character forgets everything between sessions. After this, each character keeps her own memories of lasting facts he tells her, recalls them in normal replies and when she speaks up on her own, and he can review, share, or forget any memory in Settings.

**What you'll get:** Upstream AIRI's long-term memory brought into the fork as-is: a per-character memory index in every prompt, three tools the character uses to read, save, and forget facts, memories stored on the device and visible in every window at once, a Settings page to curate them, and a toggle that removes memory from every prompt. On top of upstream: unprompted remarks can read memory, memories travel with a character when it is exported and vanish when it is deleted, the character's other model calls (notifications, image direction) know what she knows, a developer inspector shows what memory did in each turn, and the local-model benchmark exercises the memory tools.

**Why this approach:** Upstream bundles memory with recipes, background tasks, and scene sessions in one 75-file commit that conflicts with the fork's chat store and runtime in 18 files, so the memory subsystem is ported by hand at upstream's exact paths and names, which keeps later syncs cheap. The fork's own situation gate stays the only decider of when the character speaks unasked; upstream's automations are not imported.

**What it will NOT do:** No recipes, decisions, background tasks, scene bindings, or automations. No cloud sync of memories. No change to when or how often the character speaks up on her own. No other locale edits.

**Effort:** Large

**Risk:** Medium - the chat store and the core-agent runtime are touched where the fork already diverged from upstream; contract snapshots for user turns must not move.
**Decisions to sanity-check:** unprompted turns get the read tool only; a card's memories are bundled into its export package and deleted with the card; the memory index joins the prompt in the chat store rather than in the session store so the model-eval prompt hash stays identical; upstream's localStorage migration is dropped because the fork never had that data.

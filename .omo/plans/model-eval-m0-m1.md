**Who this is for and what changes for them:** Luke, when he wants to know how well a chat model follows the character's stage cues. Today that means running a side script on the Mac and reading raw replies by eye; after this, one command scores any saved set of replies with the app's own cue machinery and prints one table, on any machine.

**What you'll get:** A scoring command that replays each saved reply through the real chat runtime and stage controller, reports contract compliance separately from style heuristics, and records enough provenance to compare runs across time; a prompt command that prints the exact system prompt the app sends and its hash; an importer that turns the October Mac benchmark into the first committed dataset; a fixture suite that locks the cue rules; and docs plus a decision record for the M0-M4 levels.

**Why this approach:** The runtime itself is the oracle: replies are fed through the real runtime and stage controller instead of a re-implementation, so lab numbers cannot drift from what the app does. The contract text is rendered by one pure function the app also uses, so the prompt under test is the prompt in production, byte for byte.

**What it will NOT do:** No live model calls or overnight runner (that is M2). No persona judging by an LLM (M3). No changes to the contract wording, the parser, or the legacy side script.
